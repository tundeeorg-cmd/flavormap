## 0. How to use this document

This is a spec for an AI coding agent working alongside a Grade 10 student researcher (referred to below as **the researcher**). It defines what gets built, in what order, with what acceptance criteria.

Two categories of work appear throughout:

- **[CC]** — Claude Code executes. Scaffolding, parsing, data wrangling, plumbing, plotting, deployment.
- **[HD]** — Human Decision. A judgment call the researcher makes and records with a written rationale. Claude Code implements the decision but does not make it, and does not proceed past an open `[HD]` gate.

`[HD]` gates exist because every one of them shows up in the research paper and has to be defensible in a university interview. They are numbered `HD-1` … `HD-12` and tracked in `docs/decisions.md`.

**Authorship note for the agent:** write clean, idiomatic, well-documented code. Do not stylize output to imitate a novice, do not stage commit histories, and do not introduce deliberate errors. The honest arrangement is: the agent builds the machinery, the researcher makes and owns every analytical decision. That arrangement only holds if the `[HD]` gates are respected.

---

## 1. Non-negotiable rules

1. **Raw data is immutable.** `raw_*` tables are append-only. Cleaning writes to new tables. Never `UPDATE` or `DELETE` a raw row.
2. **Never fabricate a province.** If attribution fails, `province = NULL`. No guessing, no nearest-neighbour filling, no "probably Central."
3. **Never impute quantities.** If a recipe says "ตามชอบ," quantity is NULL and `has_quantity = false`.
4. **Never merge two canonical ingredients without an `[HD]` approval.** Automated similarity produces *candidates*, never commits.
5. **Every figure and every number in the paper is regenerated by `make figures`** from the database. No hand-edited plots, no numbers typed into the manuscript by hand.
6. **Every stochastic operation takes an explicit seed** (`RANDOM_SEED = 42`, defined once in `src/config.py`).
7. **Region is the primary unit of analysis; province is secondary.** See §7.4.
8. **Respect robots.txt and rate limits.** 1 request/second, identifying User-Agent with a contact email. If a source disallows scraping, it is dropped — not worked around.

## 3. Data model

Full DDL lives in `db/migrations/`. Key tables:

```sql
-- 001
CREATE TABLE sources (
  source_id      TEXT PRIMARY KEY,          -- 'doae', 'tat', 'wongnai', 'interview', 'cookbook'
  source_type    TEXT NOT NULL,             -- web_scraped | interview | cookbook | institutional
  base_url       TEXT,
  robots_ok      BOOLEAN NOT NULL,
  audited_on     DATE NOT NULL,
  est_recipes    INTEGER,
  province_quality TEXT                     -- explicit | region_only | none
);

-- 002  IMMUTABLE
CREATE TABLE raw_recipes (
  raw_id         BIGSERIAL PRIMARY KEY,
  source_id      TEXT REFERENCES sources,
  source_url     TEXT,
  fetched_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  http_status    INTEGER,
  raw_html       TEXT,
  parsed_json    JSONB,                     -- best-effort parse at fetch time
  content_hash   TEXT NOT NULL              -- sha256 of normalized text, for dedupe
);
CREATE UNIQUE INDEX ON raw_recipes (source_id, content_hash);

-- 003
CREATE TABLE recipes (
  recipe_id      BIGSERIAL PRIMARY KEY,
  raw_id         BIGINT REFERENCES raw_recipes,
  name_th        TEXT NOT NULL,
  name_en        TEXT,
  dish_category  TEXT,                      -- nam_prik|curry|soup|noodle|rice|yam|dessert|snack|other
  cooking_methods TEXT[],
  collection_date DATE NOT NULL
);

-- 004
CREATE TABLE canonical_ingredients (
  canonical_id   TEXT PRIMARY KEY,          -- 'ING_0047'
  name_th        TEXT NOT NULL,
  name_en        TEXT NOT NULL,
  category       TEXT NOT NULL,
  regional_note  TEXT,
  approved_by_human BOOLEAN NOT NULL DEFAULT false,
  decision_note  TEXT                       -- why this boundary was drawn (HD-3)
);

CREATE TABLE ingredient_aliases (
  alias          TEXT PRIMARY KEY,
  canonical_id   TEXT REFERENCES canonical_ingredients,
  match_method   TEXT NOT NULL,             -- manual | exact | embedding | llm
  match_score    REAL,
  approved_by_human BOOLEAN NOT NULL DEFAULT false
);

CREATE TABLE ingredient_conflations (   -- the NOT_same_as guard
  canonical_id_a TEXT REFERENCES canonical_ingredients,
  canonical_id_b TEXT REFERENCES canonical_ingredients,
  reason         TEXT NOT NULL,
  PRIMARY KEY (canonical_id_a, canonical_id_b)
);

-- 005
CREATE TABLE recipe_ingredients (
  recipe_id      BIGINT REFERENCES recipes,
  canonical_id   TEXT REFERENCES canonical_ingredients,
  raw_text       TEXT NOT NULL,             -- exactly as it appeared
  quantity_g     REAL,                      -- NULL unless convertible
  extraction_method TEXT NOT NULL,          -- llm | rule | interview
  human_validated BOOLEAN NOT NULL DEFAULT false,
  PRIMARY KEY (recipe_id, canonical_id)
);

-- 006
CREATE TABLE province_attribution (
  recipe_id      BIGINT PRIMARY KEY REFERENCES recipes,
  province_code  TEXT REFERENCES provinces,
  region         TEXT NOT NULL,
  tier           SMALLINT NOT NULL,         -- 1=explicit province 2=region 3=dish-name 4=llm
  confidence     TEXT NOT NULL,             -- high | medium | low
  method_note    TEXT,
  rationale      TEXT                       -- LLM reasoning string, kept for audit
);

-- 007  reference data, committed to git
CREATE TABLE provinces (
  province_code  TEXT PRIMARY KEY,          -- ISO 3166-2:TH, e.g. 'TH-32'
  name_th        TEXT NOT NULL,
  name_en        TEXT NOT NULL,
  region4        TEXT NOT NULL,             -- North | Northeast | Central | South
  dialect_group  TEXT NOT NULL,             -- Central | Kam_Mueang | Isaan_Lao | Dambro | Malay
  border_country TEXT,                      -- LA | KH | MM | MY | NULL
  centroid_lat   DOUBLE PRECISION NOT NULL,
  centroid_lon   DOUBLE PRECISION NOT NULL,
  geom           GEOMETRY(MultiPolygon, 4326)
);

-- 008  fieldwork
CREATE TABLE informants (
  informant_id   TEXT PRIMARY KEY,          -- 'INT_CM_001'
  province_code  TEXT REFERENCES provinces,
  age_bracket    TEXT,                      -- lt40 | 40_60 | gt60
  consent_form   BOOLEAN NOT NULL,
  consent_date   DATE NOT NULL,
  interview_date DATE NOT NULL
);
-- No names, no contact details, ever, in any table.
```

### 3.1 The analysis view

```sql
CREATE VIEW v_recipes_clean AS
SELECT r.recipe_id, r.name_th, r.dish_category,
       pa.province_code, pa.region, pa.confidence, pa.tier,
       s.source_type,
       count(ri.canonical_id) AS n_ingredients
FROM recipes r
JOIN province_attribution pa USING (recipe_id)
JOIN raw_recipes rr ON rr.raw_id = r.raw_id
JOIN sources s USING (source_id)
JOIN recipe_ingredients ri USING (recipe_id)
WHERE pa.confidence IN ('high','medium')
GROUP BY r.recipe_id, r.name_th, r.dish_category,
         pa.province_code, pa.region, pa.confidence, pa.tier, s.source_type
HAVING count(ri.canonical_id) BETWEEN 3 AND 25;
```

All analysis reads from this view. Low-confidence rows exist in the database for sensitivity analysis only and are pulled explicitly by `src/analyze/sensitivity.py`.

## 4. Reference data to assemble first

`data/reference/provinces.csv` — 77 rows, hand-checked once, committed. Columns per the `provinces` table above.

Two columns need `[HD]` sign-off because they encode contestable claims and both feed the headline analysis:

- **`dialect_group`** — the five-way split (Central / Kam Mueang / Isaan-Lao / Dambro / Malay) is a simplification. Border and transitional provinces (Tak, Phetchaburi, Chumphon, Ratchaburi) are genuinely ambiguous. **HD-1:** researcher assigns each ambiguous province, records the reasoning, and the paper reports a robustness check with the ambiguous provinces dropped.
- **`border_country`** — a province counts as a border province only if it shares a land border. **HD-2:** decide whether coastal proximity to Malaysia counts. Recommendation: no, land border only, stated explicitly.

Geometry from GADM v4.1 Thailand level-1, loaded via `scripts/load_geometry.py`.

## 6. Phase 1 — Thin end-to-end slice (Weeks 2–4)

Build the entire pipeline against **one** source and **300 recipes**. The findings will be meaningless. The point is that every interface is defined and every hard problem surfaces while it's cheap.

### 6.1 Scraper

**[CC]** `src/scrape/base.py` defines:

```python
class Scraper(Protocol):
    source_id: str
    def discover(self) -> Iterator[str]: ...          # yields recipe URLs
    def fetch(self, url: str) -> RawPage: ...         # with retry + rate limit
    def parse(self, page: RawPage) -> ParsedRecipe: ...
```

Rate limiting, exponential backoff, resumability (skip URLs whose `content_hash` already exists), and a `--limit` flag for dry runs. Raw HTML persisted to `data/raw/{source_id}/{hash}.html` *and* `raw_recipes.raw_html`.

**[HD-4]** After 300 recipes land, the researcher reads 20 by hand and writes a defect list in `docs/notebook.md`: what the parser missed, what's ambiguous, what's unusable. That list is the spec for §6.2.

### 6.2 Ingredient extraction

**[CC]** `src/clean/extract.py` — Claude API call per recipe with a structured prompt returning strict JSON:

```json
{"ingredients": [{"raw_text": "กระเทียม 3 กลีบ", "name_th": "กระเทียม",
                  "quantity": "3", "unit": "กลีบ", "confidence": "high"}]}
```

Requirements: batched with concurrency 5, responses cached by `content_hash` so re-runs cost nothing, malformed JSON retried once then flagged rather than dropped, every call's raw response stored for audit.

**[HD-5]** Researcher validates 100% of the first 50 extractions by hand, marking `human_validated = true`. Extraction proceeds to volume only after the error rate on that sample is under 5%.

### 6.3 Canonicalisation

**[CC]** Three-stage matcher in `src/clean/canonicalize.py`:
1. Exact match against `ingredient_aliases`.
2. Normalised match (strip preparation verbs: หั่น, สับ, บด, ซอย; strip quantities; NFC-normalise Thai text; collapse whitespace).
3. Embedding similarity (WangchanBERTa or `intfloat/multilingual-e5-base`) → **candidate** rows written to `alias_candidates` with `approved_by_human = false`.

Stage 3 never writes to `ingredient_aliases` directly. `scripts/review_aliases.py` prints candidates sorted by score for the researcher to accept or reject; accepted ones are inserted with `match_method='embedding'` and `approved_by_human=true`.

**[HD-6] — the most important gate in the project.** The researcher builds the first 100 canonical ingredients by hand in a spreadsheet, one row per ingredient, with a `decision_note` for every boundary drawn. Specific calls that must be recorded:
- pla ra vs. nam pla vs. nam pla ra vs. kapi — separate entries, `ingredient_conflations` rows between all pairs
- chilies: does พริกขี้หนู split from พริกชี้ฟ้า? (recommendation: yes)
- galangal vs. ginger vs. fingerroot — three entries, never merged
- fresh vs. dried turmeric — the South/North distinction depends on this
- regional cultivar variants (e.g. สับปะรดภูเก็ต) — merge to parent unless the variant is regionally diagnostic

The advisor reviews this list before Phase 3 begins.

### 6.4 Province attribution

**[CC]** `src/clean/attribute.py` implements four tiers, highest tier wins, tier recorded:

| Tier | Rule | Confidence |
|---|---|---|
| 1 | Explicit province string in title/tags/body, matched against `provinces.name_th` | high |
| 2 | Explicit region tag only → `province_code = NULL`, `region` set | high (region) |
| 3 | Dish-name lookup (`data/reference/dish_province.csv`, start at 40 entries) | high |
| 4 | Claude API structured inference from ingredients + text | high/medium/low as returned |

Tier 4 prompt must return `{"province": ..., "confidence": ..., "reasoning": ...}` and the reasoning string is stored. **Tier-4 `low` never enters `v_recipes_clean`.**

**[HD-7]** Researcher spot-checks 30 tier-4 outputs and sets the confidence thresholds. Expect a discouraging result — likely ~15–20% tier 1. Record the actual distribution; it is the empirical justification for region-primary analysis and belongs in the paper.

### 6.5 First network + map

**[CC]** Minimal `network.py` + `folium_map.py`. Co-occurrence with edge threshold ≥3, degree and betweenness centrality, choropleth of recipe counts.

**[HD-8]** Researcher inspects the top-20 centrality table. If garlic, shallot, fish sauce, and chili are not near the top, canonicalisation is broken. This is a domain-knowledge check no automated test replaces.

**Phase 1 exit:** `make all` runs end to end on 300 recipes and produces a map.

## 7. Phase 2 — Volume (Sep–Oct 2026)

### 7.1 Remaining scrapers
One module per confirmed source, same `Scraper` protocol. Target ~900–1,200 recipes total. **[CC]** entirely.

### 7.2 Dictionary to ~300 ingredients
Embedding candidates + `[HD]` review, in weekly batches of ~50. Target coverage: ≥90% of ingredient mentions mapped.

### 7.3 Fieldwork ingestion
**[CC]** `scripts/ingest_interview.py` — takes a structured YAML file per interview (informant metadata + dishes + ingredient lists as recorded) and writes to `recipes`, `recipe_ingredients` (`extraction_method='interview'`), and `province_attribution` (tier 1, high). Validation: rejects any file containing a name field, a phone number, or a free-text field longer than 500 chars, to prevent identifying data entering the database.

Target 10–12 interviews. All fieldwork under the consent and chaperone protocol in Bible §7 — the agent's role here is ingestion only.

### 7.4 The degradation rule — implement explicitly

`src/analyze/eligibility.py` computes, at the start of every analysis run:

```python
PROVINCE_MIN_N = 20            # recipes with confidence in (high, medium)
eligible_provinces = [p for p in provinces if n_recipes[p] >= PROVINCE_MIN_N]
```

- Province-level analysis (TF-IDF distinctiveness, province classifier, province Mantel) runs **only** on `eligible_provinces`.
- Region-level analysis runs on everything.
- Every province-level figure caption auto-includes `n = {len(eligible_provinces)} of 77 provinces`.
- If `len(eligible_provinces) < 12`, province-level analysis is dropped from the paper entirely and the code emits a warning, not a silent partial result.

### 7.5 Dedupe and quality
**[CC]** `dedupe.py` — exact `content_hash`, then Jaccard on canonical ingredient sets > 0.85 *and* fuzzy title ratio > 0.8, flagged for review, highest-quality source retained. Critical: this must run **before** any train/test split, or near-duplicate recipes leak across folds and inflate classifier accuracy.

**Phase 2 exit:** dataset frozen. Hard freeze — no recipes added after this date, or the analysis never converges. Freeze is a tagged git commit + a database dump to `data/exports/frozen_YYYYMMDD.sql.gz`.

## 8. Phase 3 — Analysis (Nov 2026)

Each module writes results to `data/processed/*.parquet` and is called by `make analyze`. All modules take `--seed`.

### 8.1 `network.py`
Co-occurrence graph, weighted undirected. Edge threshold as a parameter; run at 2, 3, and 5 and report the sensitivity table in the appendix. Four regional subgraphs plus the national graph. Export GraphML.

### 8.2 `centrality.py` (RQ1)
Degree, betweenness (weighted), PageRank, eigenvector. **Add a null model:** compare observed centrality ranks against 1,000 degree-preserving configuration-model rewirings, so "garlic is central" is reported with a z-score rather than as a bare observation.

### 8.3 `communities.py` (RQ2)
Louvain across resolution γ ∈ {0.6, 0.8, 1.0, 1.2, 1.5}, 100 seeds each, consensus partition via co-assignment matrix. Report modularity, and alignment with `region4` via NMI and ARI. **Both metrics need a null distribution** — permute region labels 1,000 times and report the observed NMI's percentile. An NMI of 0.3 means nothing without it.

### 8.4 `distinctiveness.py` (RQ3)
TF-IDF over province documents — but raw TF-IDF is confounded by recipe count per province. Required correction:

```python
# bootstrap: subsample to a fixed n per province, 1000 iterations
for i in range(1000):
    sample = {p: rng.choice(recipes[p], size=PROVINCE_MIN_N, replace=False)
              for p in eligible_provinces}
    tfidf_i = compute_tfidf(sample)
# report mean score + 95% percentile CI per (province, ingredient)
```

Only ingredients whose CI excludes the cross-province median are reported as distinctive.

### 8.5 `cluster.py`
UMAP (`n_neighbors=10, min_dist=0.1, metric='cosine'`) for **visualisation only** — never as input to a statistical test. PCA alongside it for comparison. K-means at k ∈ {4,6,8} with silhouette scores, plus Ward hierarchical clustering with a dendrogram (the more interpretable figure for the paper). Clustering runs on the full TF-IDF matrix, not the UMAP projection.

### 8.6 `spatial.py` (RQ4) — the corrected version

Three fixes to the Bible's code, all required:

**(a) Moran's I on a real scalar.** Not `umap_dim1`. Run on per-province distinctiveness score and on the top-3 individual ingredient prevalences. Queen contiguity weights, with a KNN(k=5) fallback matrix for provinces with no queen neighbours (Phuket) — report both.

**(b) Mantel by permutation, not `pearsonr`.**

```python
def mantel(d1, d2, n_perm=9999, seed=42):
    idx = np.triu_indices(d1.shape[0], k=1)
    r_obs = pearsonr(d1[idx], d2[idx])[0]
    rng, count = np.random.default_rng(seed), 0
    for _ in range(n_perm):
        perm = rng.permutation(d1.shape[0])
        r_perm = pearsonr(d1[np.ix_(perm, perm)][idx], d2[idx])[0]
        count += (abs(r_perm) >= abs(r_obs))
    return r_obs, (count + 1) / (n_perm + 1)
```

**(c) Partial Mantel — this is what actually answers the research question.** Build three distance matrices over eligible provinces:

| Matrix | Definition |
|---|---|
| `D_culinary` | cosine distance between province TF-IDF vectors |
| `D_geo` | haversine distance between centroids (km) |
| `D_lang` | 0 if same `dialect_group`, 1 otherwise |
| `D_border` | 0 if same `border_country` (both NULL counts as same), 1 otherwise |

Then: does `D_culinary ~ D_geo` survive controlling for `D_lang`? Does `D_culinary ~ D_lang` survive controlling for `D_geo`? Report all four partial Mantel statistics in one table. "Geography vs. trade routes vs. linguistic boundaries" is the Bible's stated research question, and this table is the only thing in the project that answers it.

### 8.7 `classifier.py` (RQ5)
- **Primary:** 4-class region. **Secondary:** province, restricted to `eligible_provinces`.
- Features: multi-hot canonical ingredients. Compare LogisticRegression (L2), RandomForest, GradientBoosting.
- **Baselines, always reported:** majority class, and a model using only `n_ingredients`. Accuracy above chance means nothing without them.
- **Macro-F1 as the headline metric**, not accuracy — the classes are badly imbalanced.
- 5-fold stratified CV, grouped by `content_hash` cluster so near-duplicates cannot straddle folds.
- Confusion matrix + permutation feature importance (not Gini importance, which is biased toward high-cardinality features).
- **Cross-method validation:** the top-20 features by permutation importance should overlap substantially with the TF-IDF distinctive ingredients from §8.4. Compute the rank correlation between the two lists and report it. Agreement between independent methods is the strongest evidence in the paper; disagreement is a finding worth investigating, not a bug to hide.

### 8.8 `sensitivity.py`
Re-run §8.4–8.7 including `confidence='low'` rows, and again with `PROVINCE_MIN_N = 30`. Report whether conclusions change. One appendix table.

Interview data released as anonymised dish-level records only — never transcripts, never anything traceable to an informant.

### 9.4 Reproducibility check
Fresh clone + database dump + `make all` on a different machine must reproduce every number in the paper. Run this before arXiv submission, not after.
